TLS 指纹（ClientHello 伪装）














上游阿里云 ESA WAF 会检查 TLS ClientHello 指纹（JA3）。ZCode 桌面端是 Electron/Chromium，默认 Chrome 伪装与其一致；被风控时可换 firefox/随机化尝试。








说明




· 指纹作用于所有上游请求（额度/活动/聊天转发）的 TLS 握手层。


· 自定义 JA3 为 5 段格式：版本,密码套件,扩展,椭圆曲线,点格式；未识别扩展会跳过。


· HTTP/2 已禁用（ESA WAF 不支持 h2 ALPN），与桌面客户端实测行为一致。

















人机验证（阿里云无痕）

























说明




· zcode.z.ai 免费额度通道需要 X-Aliyun-Captcha-Verify-Param，由本机真实 Chrome/Edge 无头求解（捆绑 Chromium 会被风控识别）。


· 参数缓存 45 秒，过期后 5 分钟宽限期内复用旧参数并后台刷新。


· 数据中心 IP 会被风控（F001 环境风险），建议在「出口代理」配置住宅代理。


· 自动模式连续失败 2 次会弹出有头浏览器窗口，人工完成验证后参数同样进入缓存。

API 文档


把网关接到任意 OpenAI / Anthropic 兼容客户端








2API 端点




鉴权：Authorization: Bearer sk-xxx 或 x-api-key: sk-xxx（在「设置 → 账号安全」生成）






端点协议说明



POST /v1/messagesAnthropic Messages原生协议直通，支持 SSE 流式


POST /v1/chat/completionsOpenAI Chat自动转换为 Anthropic 上游请求，支持 tools / 流式 / include_usage


POST /v1/responsesOpenAI ResponsesCodex / 新版 OpenAI SDK 兼容，含 function_call 事件流


GET /v1/models通用模型清单（同时带 OpenAI 与 Anthropic 字段）







可选请求头：x-zcode-group: 组名 限定只用某分组的账号。


模型名大小写不敏感（glm-5.3 → GLM-5.3），支持 bigmodel/ 前缀路由到 BigModel 通道。


curl 示例


curl http://127.0.0.1:8687/v1/chat/completions \
  -H "Authorization: Bearer sk-你的KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"GLM-4.5-Flash","messages":[{"role":"user","content":"你好"}],"stream":true}'
